# 用户编码习惯

## 编译规范

### 1. 只能编译 Release 版本，禁止编译 Debug 版本

- **仅允许使用 `Release` 配置进行编译**。
- **禁止使用 `Debug` 配置进行编译**，不得生成 Debug 版本的二进制文件。
- 提交代码前请确保 `obj/` 和 `bin/` 目录下仅保留 `Release` 构建产物，清理 `Debug` 相关输出。

## 代码规范

### 2. 禁止魔法数字和硬编码常量

- 所有魔法数字、硬编码字符串必须提取为命名常量。
- 常量按用途分组，放在文件顶部或专用常量类中。
- 示例：`60000` → `const long MillisPerSecond = 1000;`

### 3. 函数职责单一

- 每个函数只做一件事，且做好这件事。
- 函数过长（超过 30 行）应拆分为更小的私有方法。
- 函数名应准确描述其行为，避免模糊命名。

### 4. 文件职责单一

- 每个文件只承担一个明确的职责。
- 一个文件不应包含多个不相关类的定义。
- 大文件应按逻辑拆分为多个小文件。

### 5. 代码中不使用注释

- 代码应通过清晰的命名和结构自解释。
- 禁止使用行内注释、块注释、XML 注释。
- 需要说明逻辑时，应重构代码使其更直观，而非添加注释。

### 6. 清理死代码与冗余代码

- 删除未使用的字段、方法、类、导入。
- 删除永远为 `true` 或 `false` 的条件分支。
- 删除重复逻辑，提取为公共方法。
- 定期审查代码，移除废弃功能。

### 7. 代码风格保持解耦

- 类之间避免循环依赖。
- 依赖通过接口或构造函数注入，而非静态全局状态。
- 避免过大的类（上帝类），合理拆分职责。
- 使用不可变数据结构传递数据，减少副作用。
